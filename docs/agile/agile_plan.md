# Agile Development Plan

## 1. Project Overview & Context
* **Project Name:** UniBites App (Campus Cafeteria Pre-Order System)
* **Target Environment:** Walter Sisulu University (WSU) Campus Cafeteria
* **Core Objective:** To mitigate peak-hour cafeteria queues, minimize food wastage, and allow students and staff to seamlessly browse menus, submit pre-orders, and select designated pickup time slots.

---

## 2. Agile Methodology Chosen
The team has adopted the **Scrum Framework** to manage the lifecycle of this project. Given the 12-week development roadmap, the Scrum methodology allows the team to work in iterative blocks, frequently evaluate progress through development boundaries, maintain continuous feedback loops, and rapidly adapt to technical integration blockers.

## 4. Sprint Schedule
The semester's roadmap is structured into **six distinct, 2-week sprint cycles** to maintain a reliable delivery cadence:

* **Sprint 1 (Weeks 1–2):** Project initialization, repository infrastructure, architecture decomposition blueprints, and core schema validation.
* **Sprint 2 (Weeks 3–4):** Core transaction engineering—interactive food selection forms, transactional API controllers, and pickup window slot allocation logic.
* **Sprint 3 (Weeks 5–6):** Component integration, full system loop testing, connection optimization, and bug patch iterations.
* **Sprint 4 (Weeks 7–8):** Vendor dashboard implementation, real-time demand calculation metrics, and state persistence adjustments.
* **Sprint 5 (Weeks 9–10):** Deployment configuration initialization, production environment staging, security configuration audits, and performance tuning.
* **Sprint 6 (Weeks 11–12):** End-to-end user acceptance testing (UAT), comprehensive technical documentation compilation, and deployment sign-offs.

### Agile Ceremonies & Frequency:
* **Daily Stand-ups:** Conducted asynchronously via WhatsApp at 8:00 AM every weekday to outline yesterday's accomplishments, today's targets, and immediate blockers.
* **Weekly Sprint Syncs:** Held every Friday evening via Microsoft Teams for formal sprint execution adjustments, system code reviews, and cross-functional pair-programming coordination.
* **Sprint Planning & Retrospectives:** Executed at the boundary threshold of every 2-week cycle to demo working increments, evaluate pipeline workflow health, and commit to process refinements.

## 5. Communication & Collaboration Tools
The team relies on a standard suite of collaborative software tools to ensure absolute visibility and data tracking:

* **GitHub:** Serves as the single source of truth for all source control management, code tracking, branch review workflows, automated commit logs, and Kanban task board item monitoring.
* **WhatsApp:** Utilized for rapid, low-latency, asynchronous communication, urgent blocker alerts, and daily morning scrum check-ins.
* **Microsoft Teams:** Utilized as the primary channel for high-fidelity virtual conference sessions, formal sprint reviews, live technical demonstrations, and visual system screen shares.
* **Google Docs:** Employed for real-time collaborative drafting, shared note-taking during brainstorming sessions, and compilation of raw administrative and meeting logs.
